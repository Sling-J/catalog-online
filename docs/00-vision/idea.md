# Идея: автогенерируемый онлайн-каталог для малых магазинов

> Рабочее название: **catalog-online**. Это исходная формулировка идеи. Критика и риски — в [idea-evaluation.md](idea-evaluation.md).

## 1. Одной фразой

SaaS, который превращает складской учёт малого магазина (кассовая программа, 1С, сканер штрихкодов) в готовый онлайн-каталог с остатками, размерами и ценами, без разработки сайта под каждого клиента.

## 2. Проблема

В городах много небольших розничных магазинов (первый фокус — детская одежда), у которых нет своего сайта и каталога:

- Вся «витрина» — Instagram: список товаров неполный, быстро устаревает.
- Покупатель не знает, **что есть в наличии, какие размеры, сколько осталось, какая цена** — приходится писать в директ/WhatsApp и ждать ответа.
- Владелец тратит время на однотипные ответы «есть ли размер X?», теряет клиентов, которым не ответили вовремя.
- При этом учёт товара у магазина уже ведётся (сканер штрихкодов → чек → списание остатка в 1С или другой системе), но эти данные нигде не публикуются.

## 3. Решение

Единый сервис, где у каждого магазина автоматически появляется собственный каталог:

1. **Данные берутся из учётной системы магазина** (интеграция: API, выгрузка файлов, агент на кассе), а не вводятся руками повторно.
2. Каталог публикуется на отдельной странице магазина (поддомен/свой домен): категории, фильтры, сортировка, размеры, остатки, цены.
3. **Оформление заказа без онлайн-оплаты**: покупатель собирает корзину, и список товаров уходит менеджеру в WhatsApp. Менеджер подтверждает, остатки в каталоге резервируются/списываются.
4. Фотографии и описания добавляются владельцем отдельно (интеграция может приносить товары без картинок).

Сознательно **не делаем**: главную с баннерами, конструктор сайтов, онлайн-эквайринг, доставку. Только каталог + заявка.

## 4. Целевая аудитория

- **Клиент (платит):** небольшой розничный магазин, 1–3 точки, 100–5000 SKU, есть учётная система и сканер. Первый сегмент — детская одежда в одном городе.
- **Конечный пользователь:** покупатель из города, который хочет быстро увидеть наличие и размер и отправить заявку.

## 5. Ключевая ценность

| Для магазина | Для покупателя |
|---|---|
| Сайт-каталог без разработки и ручного ввода | Видит актуальные остатки и размеры без переписки |
| Меньше однотипных вопросов в мессенджерах | Быстро собирает заказ и отправляет в WhatsApp |
| Данные синхронизируются сами | Фильтры, сортировка, категории |

## 6. Главная технологическая ставка

**Универсальный слой интеграции с учётными системами.** Это и главный ров (moat), и главный риск. Системы у магазинов разные (1С разных конфигураций, самописные, облачные кассовые программы). Подход: набор адаптеров под общий внутренний формат товара/остатка; приоритет — самые популярные системы в целевом регионе; для закрытых систем — запасные пути (экспорт в файл, импорт Excel/CSV, агент на компьютере кассы). Подробнее — в [03-integrations](../03-integrations/README.md).

## 7. Гипотезы, которые нужно проверить

| # | Гипотеза | Как проверить |
|---|---|---|
| H1 | Магазины готовы платить за каталог с остатками | Интервью 15–20 магазинов, предпродажа |
| H2 | Покупатели действительно пойдут в каталог, а не в Instagram/WhatsApp | Пилот на 3–5 магазинах, метрика: заявки из каталога |
| H3 | Большинство магазинов региона используют ограниченное число систем | Опрос + список используемых систем |
| H4 | Данных из учётной системы достаточно (название, размер, остаток, цена, штрихкод) | Разбор выгрузок реальных магазинов |
| H5 | Остатки синхронизируются достаточно часто, чтобы не было «продали, а в каталоге есть» | Пилот, замер расхождений |

## 8. Идея поэтапного запуска (предварительно, не финально)

1. **Этап 0 — валидация:** интервью и ручной пилот (каталог из Excel/CSV, без интеграций).
2. **Этап 1 — MVP:** мультиарендный каталог, импорт CSV/Excel, фото, корзина → WhatsApp (уточнено D14: заказы в сервисе не храним), ручное подтверждение.
3. **Этап 2 — первая интеграция** с самой популярной системой у пилотных клиентов.
4. **Этап 3 — масштабирование** интеграций и онбординга.

Состав MVP будет определён отдельным документом в `01-product/`.
