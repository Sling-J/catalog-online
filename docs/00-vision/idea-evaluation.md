# Оценка идеи: сильные стороны, риски, корректировки

Первичная оценка до какой-либо валидации. Это гипотезы и рассуждения, а не факты; рыночных данных здесь нет.

## Вердикт

Идея **здравая и узкая**, проблема реальная и понятная. Но центр тяжести не в «сайте-каталоге» (это легко), а в **интеграции с учётными системами** и в **доверии к актуальности остатков**. Рекомендация: не начинать с универсальных интеграций, а сначала доказать спрос на каталоге с простой загрузкой данных.

## Сильные стороны

- Конкретная боль с понятным измеримым результатом (меньше переписок, больше заявок).
- Не нужны эквайринг, доставка, склад: меньше регуляторики и операционных рисков.
- Данные уже есть в учётной системе магазина, повторный ввод не нужен.
- Один продукт для многих похожих клиентов: один код, много магазинов (мультиарендность), а не сайт под заказ.
- Хороший вертикальный фокус (детская одежда): размерная сетка, возраст, сезонность.

## Главные риски

### 1. Интеграции — самое сложное
- Каждая 1С — «снежинка»: типовые и сильно доработанные конфигурации, разные версии, часто нет открытого API, база стоит на локальном компьютере без доступа из интернета.
- «Научиться интегрироваться почти со всеми» — бесконечный проект. Без приоритизации стартап утонет в адаптерах.
- Поддержка интеграций (обновления 1С, смена кассовой программы) — постоянные операционные затраты.

### 2. Актуальность остатков
- Если в каталоге «есть», а в магазине уже продано — доверие падает быстрее, чем растёт ценность. Нужны: частота синхронизации, резервирование, статус «уточнить наличие», показ остатка диапазоном («мало»), а не точным числом.
- Конфликт: товар продан в офлайне, пока заказ ждёт подтверждения менеджера.

### 3. Спрос и готовность платить
- Не проверено, что магазины заплатят и что покупатели будут пользоваться каталогом, а не мессенджером. Instagram + WhatsApp «и так работают» для владельцев.
- Малый бизнес чувствителен к цене; возможна высокая текучка клиентов (churn).

### 4. Конкуренция и замена
- Конструкторы (Tilda, Shopify и подобные), маркетплейсы, готовые витрины внутри облачных учётных систем (например, МойСклад и аналоги), Telegram/WhatsApp-каталоги. Нужно изучить, что есть именно в целевой стране/регионе.
- Наше отличие должно быть не «каталог», а «ноль ручной работы + подключение к вашей кассе».

### 5. Качество данных
- В учётных системах номенклатура часто грязная: нет единой структуры «товар → размеры», названия с мусором, дубликаты, нет категорий, нет атрибутов (размер, цвет, возраст).
- Автоматическая нормализация (возможно, с ИИ) — отдельная задача и отдельный источник ценности.

### 6. Онбординг и поддержка
- Подключение интеграции у каждого клиента может требовать человека (установка агента, доступы). Это бьёт по юнит-экономике, если продаётся дёшево.

### 7. Юридическое
- Персональные данные покупателей (номер телефона, заказ) — локальное законодательство. WhatsApp-ссылки (wa.me) не требуют API, но Business API платный и требует модерации.

## Корректировки идеи

1. **Разделить продукт на два независимых слоя:** (а) каталог + корзина + WhatsApp; (б) источники данных (импорт файлов → интеграции). Слой (а) должен жить без (б) с самого дня 1.
2. **Источник данных по уровням, от простого к сложному:**
   1. Ручная загрузка Excel/CSV (MVP).
   2. Автоматическая загрузка файла (экспорт из кассовой программы по расписанию, почта/папка).
   3. API облачных систем.
   4. Локальный агент для 1С (выгрузка по HTTP/через COM/OData).
3. **Выбрать 1–2 системы** по результатам интервью и делать интеграцию только под реально подписавшихся клиентов (customer-funded integrations).
4. **Не обещать «точный остаток»,** а показывать «в наличии / мало / нет» + дата последней синхронизации.
5. **Зафиксировать единую внутреннюю модель** (товар, вариант/SKU, остаток, цена, штрихкод) — адаптеры только преобразуют внешние данные в неё.
6. **Фото:** привязка по штрихкоду/артикулу; в перспективе — быстрая загрузка со смартфона, подбор по штрихкоду, общая библиотека фото одинаковых товаров.
7. **Монетизация (гипотеза):** подписка на магазин, тарифы по числу SKU/точек; плата за подключение интеграции. Проверять на интервью.

## Метрики успеха (черновик)

- Магазинов в пилоте и доля платящих.
- Заявок из каталога на магазин в неделю.
- Доля заявок, подтверждённых менеджером (отражает точность остатков).
- Время подключения нового магазина (цель: часы, а не дни).
- Расхождение остатков каталог vs. учётная система.
