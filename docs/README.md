# Документация catalog-online

Единая точка входа. Здесь карта документации и правила, как её читать и вести.

## С чего начать

1. [status.md](status.md): где проект сейчас и что дальше.
2. [00-vision/idea.md](00-vision/idea.md): что за продукт и зачем.
3. [00-vision/idea-evaluation.md](00-vision/idea-evaluation.md): риски и корректировки идеи.
4. [06-process/workflow.md](06-process/workflow.md): как мы работаем, стадии.
5. [open-questions.md](open-questions.md): что ещё не решено.
6. [glossary.md](glossary.md): термины (SKU, вариант, адаптер и т.д.).

## Карта

| Раздел | Что внутри | Кто пишет / читает | Состояние |
|---|---|---|---|
| [00-vision](00-vision/) | Идея, оценка, цели, позиционирование | Основатель; читают все | идея записана |
| [01-product](01-product/) | Исследование, персоны, user stories, объём MVP, требования | Аналитик / продукт | MVP и ТЗ приняты |
| [02-architecture](02-architecture/) | Архитектура, модель данных, ADR (решения) | Архитектор / разработка | пусто |
| [03-integrations](03-integrations/) | Исследование учётных систем, матрица поддержки, спецификации адаптеров | Аналитик + разработка | пусто |
| [04-design](04-design/) | UX-потоки, макеты, UI-гайд | Дизайн | пусто |
| [05-tasks](05-tasks/) | Бэклог, роадмап, спринты | Планирование | пусто |
| [06-process](06-process/) | Как работаем: роли, правила документов, Definition of Done | Все | процесс и роли приняты |

Нумерация задаёт порядок чтения: от «зачем» (00) к «как» (02–04) и «когда» (05).

## Как читать

- **Новый человек:** vision → open-questions → product → architecture.
- **Разработчик:** architecture (+ ADR) → integrations → tasks.
- **Аналитик:** vision → product → integrations → open-questions.
- **Дизайнер:** vision → product (персоны, user stories) → design.

## Правила ведения документов

Подробнее: [06-process/documentation-rules.md](06-process/documentation-rules.md). Кратко:

- Каждый документ начинается с front matter: `status` (`draft` / `review` / `accepted` / `outdated`), `owner`, `updated`.
- Одна тема — один файл. Имена файлов: `kebab-case`, латиница.
- У каждого раздела есть свой `README.md` с оглавлением; новый документ добавляется в него.
- Архитектурные решения фиксируются отдельными файлами ADR (`02-architecture/adr/NNNN-название.md`), старые не переписываются, а заменяются новыми.
- Открытый вопрос идёт в [open-questions.md](open-questions.md), решённый переезжает в ADR или в профильный документ.
- Ссылки между документами относительные.
- Документы на русском; идентификаторы, код и термины-аббревиатуры допускаются на английском.
