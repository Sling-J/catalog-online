# Грабли: технические ошибки и обходы

Что в ходе работы не запустилось, упало или сработало не так, и как это обошли. Цель — не наступать второй раз. Читать перед задачей (особенно разделы «Окружение» и «Проверка»); пополнять в той же сессии, когда случилось (решение основателя 2026-11-08).

Здесь не продуктовые решения и не предложения (они — в `04-design/`, ADR, `ideas.md`), а технические факты: «сделал так → получил это → правильно так».

Формат записи: **что случилось** → **почему** → **как правильно**. В скобках — дата и задача, где всплыло.

## Окружение и команды

- **`pnpm` / `npm` не находятся** (было до 2026-11-08): `nvm install` положил в папку версии только `node.exe` — архив с npm и corepack не докачался, ошибки не было. Починено так: официальный `node-v<версия>-win-x64.zip` с nodejs.org распаковать и скопировать в `%LOCALAPPDATA%
vm<версия>` всё, кроме `node.exe` (он занят запущенными дев-серверами и тот же самый), потом `corepack enable`. Проверка: `pnpm -v` в репозитории — 10.18.1. Если снова «не найдено» — сначала посмотреть, есть ли в папке версии `node_modules
pm` и `corepack.cmd` (2026-11-07, 2026-11-08, T-310).
- **Длинный heredoc в Bash падает** с `unexpected EOF while looking for matching '` — на файлах с JSX и кириллицей, хотя ограничитель в кавычках. → Файлы писать инструментом Write; правки в нескольких местах — Python-скриптом, сохранённым в scratchpad через Write и запущенным `python <файл>` (2026-11-08, T-310).
- **Python `write_text` на Windows пишет CRLF** (переводит `
` в `
`): документы, которые не трогает Prettier, меняют концы строк целиком. → `write_text(s, encoding="utf-8", newline="
")` или после — `sed -i 's/
$//' <файл>` (2026-11-08, T-311).
- **Дев-серверы уже запущены** основателем (витрина :3000, админка :3002 и :3012). Новый `vite --port 3012 --strictPort` падает: порт занят. → Сначала `curl -s -o /dev/null -w "%{http_code}" http://localhost:3012/`; если 200 — работать с ним, он подхватывает правки сам (2026-11-08, T-310).
- **Дев-сервер админки на :3012, запущенный до перехода контракта на исходники**, берёт `@catalog/contract` из `dist`: новые обработчики MSW в браузере не работают, запрос уходит мимо моков (в сети его нет, форма пишет «Не получилось»). Видно по `curl -s http://localhost:3012/src/app/mocks/start-mocks.ts` — в импорте `contract/dist/msw.js`. → Не перезапуская сервер основателя: `pnpm --filter @catalog/contract build` (2026-11-08, T-311).

## Пакеты монорепо

- **`@catalog/contract` отдавался только из `dist`** (до 2026-11-08): поменял моки — дев-сервер молча показывал старое, пока пакет не пересобран. Исправлено (решение основателя 2026-11-08): в `exports` контракта условие `development` → `src/*.ts`; Vite в разработке (браузер и SSR) и Vitest берут исходники, `vite build` (`production`) и `tsc` — `dist`. Остался хвост: после правки **типов** контракта `tsc` приложений видит старые `.d.ts`, пока не прошёл `pnpm build` / `pnpm check` (turbo собирает контракт сам). Запущенный до правки `package.json` дев-сервер надо перезапустить. `@catalog/ui` отдаётся из исходников всегда (2026-11-08, T-310).
- **`routeTree.gen.ts` админки** создаёт плагин роутера при `vite build` / `vite dev`. Добавил файл маршрута — `tsc` ругается на неизвестный путь, пока не прошла сборка. → После нового маршрута сначала `vite build` (или дать поработать дев-серверу), потом `tsc` (2026-11-08, T-310).
- **FSD запрещает импорт между срезами одного слоя** (`features/a` → `features/b`). Нужное двум фичам — переносить вниз: общий UI без бизнес-контекста — в `shared/ui`, данные и форматирование сущности — в `entities/<сущность>/lib`. Хук одной фичи можно отдать странице через `index.ts` фичи (страница выше слоем) (2026-11-08, T-310).

## Сверка с макетом (`design:compare`)

- **Однострочный `<input>` вместо многострочного текста макета** — всё ниже съезжает (в отчёте одинаковый сдвиг у всех следующих строк). Если в макете текст поля в две строки — нужен `TextAreaField` (2026-11-08, T-310, «Как найти»).
- **Поле с пустой подписью в макете** (`field("", …)` в генераторах) всё равно даёт отступ 6 px сверху — `margin-bottom` пустой строки подписи. Повторять в коде (2026-11-08, T-310, контакты на телефоне).
- **Размеры в макете — `content-box`**: `height: 40px` плюс рамка 1.5 px дают больше 40. Не угадывать — подбирать по цифрам отчёта, пока шаг строк не совпадёт (2026-11-08, T-310: поле времени 42 px).
- **`Switch` из `@catalog/ui` с подписью только для дикторов** (`sr-only`) сдвигает переключатель на 12 px: у кнопки `gap-3`, а обёртка подписи — пустой элемент flex. → `className="w-auto gap-0"` (2026-11-08, T-310).
- **Вставка нового поля** сдвигает всё ниже дальше `--max-shift` (24 px), и отчёт пишет «совпало 5 из 23» — это не поломка. → Перепроверить с `--max-shift 100`: если у всех один и тот же сдвиг, вёрстка цела (2026-11-08, T-310).
- **`cx` из `@catalog/ui` только склеивает классы**, не заменяет: `className="w-auto gap-2"` у `Switch` (у него `w-full gap-3`) не действует — побеждает то, что позже в CSS. Переключатель растянулся и съел название рядом. → Обёртка `<span className="flex-none">` вокруг `Switch` и `gap-2!` (важность в Tailwind v4 — `!` в конце) (2026-11-08, T-311).

## Проверка в браузере

- **Свой скрипт Playwright** для сценариев, которых нет в `design:compare` (клики, ввод, iframe): положить временно в `tools/design-compare/` (там есть `playwright-core`, канал `chrome`) и удалить после. Ошибки гидратации и исключения ловит `page.on('pageerror')`, содержимое iframe с другого адреса — `page.frames()` (2026-11-08, T-310).
- **`getByRole(…, { name: 'Точное количество' })` в Playwright ищет по вхождению**, а имя кнопки-карточки — весь её текст: совпали обе карточки («…не видно» у первой). → Давать карточке имя заголовком (`aria-labelledby`, пояснение — `aria-describedby`) — так и дикторам понятнее; или `exact: true` (2026-11-08, T-312).
- **Закрытые шторки остаются в DOM** (`<dialog>` без `open`): в Playwright `getByLabel('Название')` находит поля всех шторок и падает на строгом режиме. → Искать внутри открытой: `page.locator('dialog[open]').getByLabel(…)` (2026-11-08, T-311).
- **Превью витрины принимает правки только с адреса админки** `http://app.localhost:3002` (проверка `origin`). На :3012 витрина в iframe откроется, но правок не покажет — не баг (2026-11-08, T-310).

## React, TanStack, приложения

- **TanStack Form: `form.reset(values)` меняет `defaultValues` формы**, а `useAppForm({ defaultValues })` на следующей отрисовке может вернуть старые (поле не тронуто — значения «обновляются» из опций). → Исходные значения держать в `useState` и после сохранения менять и их, и форму: `setInitial(v); form.reset(v)` (2026-11-08, T-310, `useShopInfoForm`).
- **Выход из админки через `queryClient.clear()` + `navigate('/login')`** не годится: `/login` в `beforeLoad` видит `me` в кеше и отправляет обратно, а очистка под открытым экраном вызывает перезапросы с 401. → `window.location.assign('/login')` после `logout` (2026-11-08, T-310).
- **`postMessage` во время гидратации витрины** (правка из админки пришла раньше, чем ожила страница) — ошибка гидратации: `setQueryData` меняет данные ещё не гидрированной части. → Витрина шлёт `ready` после события `load` и двух кадров (`use-shop-draft.ts`) (2026-11-08, T-310).
- **Ключ со значением `undefined` в сообщении превью** затирает поле при `{ ...saved, ...draft }`. → Необязательные поля не класть в объект вовсе, а не ставить `undefined` (2026-11-08, T-310, `previewFromDraft`).
- **Запись в `ref` во время отрисовки** (`ref.current = x` в теле компонента) ругает линтер хуков. → Обновлять в `useEffect` (2026-11-08, T-310).
