# Правила ведения документации

1. **Front matter** в каждом документе: `status` (`draft` → `review` → `accepted` → `outdated`), `owner`, `updated` (дата).
2. **Один файл — одна тема.** Разрастается больше ~300 строк, делим.
3. **Именование:** латиница, `kebab-case`, каталоги разделов с номерами (`00-`…`06-`).
4. **README в каждом разделе** содержит оглавление и статусы; новый документ добавляется туда же.
5. **Ссылки** относительные, между документами ссылаемся, а не копируем текст.
6. **Решения** (архитектурные и продуктовые) оформляются ADR; принятые не переписываются, а заменяются.
7. **Факт против гипотезы:** гипотезы явно помечаем («гипотеза», «предварительно»); проверенное указываем с источником (интервью, замер).
8. **Открытые вопросы** живут в [../open-questions.md](../open-questions.md); при решении вопрос переносится в профильный документ/ADR и отмечается закрытым.
9. **Устаревшее** не удаляем сразу: ставим `status: outdated` и ссылку на актуальный документ.
10. **Язык:** русский; код, идентификаторы и принятые термины можно на английском.
