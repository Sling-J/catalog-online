# Роли, агенты и инструменты

## Подход

Не ставим готовые универсальные наборы агентов (Superpowers, BMAD и т.п.) целиком. По опыту сообщества ([исследование](research-claude-workflows.md#3-опыт-сообщества-про-агентов-важно-для-нас)) большой набор агентов путает маршрутизацию и добавляет церемоний. Берём из них идеи, а инструменты собираем под проект по мере необходимости.

**Роль = «шляпа» + шаблон документа.** Основная сессия Claude надевает нужную шляпу на нужной стадии. Отдельный агент создаётся, только если задача требует изолированного контекста.

## Роли

| Роль | Стадия | Чем занимается | Кто ведёт | Артефакты |
|---|---|---|---|---|
| Продукт/аналитик | 1 | Интервью основателя, сценарии, MVP, требования | Claude спрашивает, основатель решает | `01-product/*` |
| Дизайнер | 2 | Варианты стиля, дизайн-система, экраны, переходы | Claude + дизайн-скиллы, основатель выбирает | `04-design/*` |
| Архитектор | 3 | Стек, модель данных, контракт API, ADR | Совместно, решение за основателем | `02-architecture/*` |
| Планировщик | 4 | Эпики, задачи, порядок | Claude предлагает, основатель утверждает | `05-tasks/*` |
| Разработчик | 5–6 | Реализация по задачам | Claude, основатель ревьюит | код |
| Ревьюер | 5–6 | Сверка изменений с требованием/ADR, баги | Субагент (когда появится) + основатель | замечания |
| QA | 5–6 | Проверка в браузере, сценарии | Claude в браузере, позже субагент | отчёт |

## Субагенты (план, создаём по необходимости)

Максимум 2–3 штуки с непересекающимися задачами. Описываются в `.claude/agents/`.

| Агент | Когда создать | Инструменты | Модель |
|---|---|---|---|
| `researcher` | Когда понадобится объёмный поиск (интеграции, библиотеки, конкуренты) | только чтение + веб | дешевле основной |
| `reviewer` | С началом стадии 5 | только чтение | сильная |
| `qa-browser` | Когда будут сквозные сценарии в UI | браузер, только чтение кода | средняя |

## Skills проекта (кандидаты)

Создаём, когда действие повторилось 2–3 раза. Живут в `.claude/skills/`.

- `/adr` — оформить решение по шаблону и добавить в журнал.
- `/feature-spec` — оформить сценарий/требование по шаблону.
- `/handoff` — обновить `docs/status.md` в конце сессии.

## Внешние скиллы и плагины

Подключаем точечно под стадию, решение фиксируем здесь.

| Скилл / MCP | Стадия | Статус |
|---|---|---|
| Context7 MCP — актуальная документация библиотек (`.mcp.json`) | все | подключён 2026-10-31 |
| Impeccable 4.8.0 (pbakaus/impeccable, commit b7a8917) — дизайн всех поверхностей: режим Persuade для лендинга и витрины, Operate для админки (`.claude/skills/impeccable/`) | 2, 5 | установлен 2026-10-31 |
| Taste skill (Leonxlnx) — пересекается с Impeccable, конфликт правил | — | не ставим; вернуться, только если Impeccable не даст нужного «вау» на лендинге |
| Emil Kowalski: `emil-design-eng`, `review-animations` — микро-анимации | 5 | поставить на стадии фронтенда |

Примечание по Impeccable: при первом запуске его лаунчер скачивает бинарник движка с GitHub Releases проекта и сверяет SHA-256 с `scripts/engine-checksums.txt`. Без движка скилл работает в упрощённом режиме (читает PRODUCT.md/DESIGN.md напрямую).
