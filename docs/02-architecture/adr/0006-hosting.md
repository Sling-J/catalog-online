# 0006. Хостинг: ps.kz, один VPS в Казахстане

## Контекст
- ADR 0001 оставил открытым, где хранить данные: от этого зависит закон РК о персональных данных (NFR-9, T-601). Устройство уже выбрано: Docker Compose на одном VPS (web, admin, staff, api, worker, postgres, Caddy) и S3-совместимое хранилище файлов — два бакета, публичный и закрытый (ADR 0001, примечание T-405).
- **Какие персональные данные у нас есть.** Покупателей не храним (D11). Владельцы магазинов и сотрудники: почта (`accounts`, `staff_users`), WhatsApp магазина — у ИП обычно личный номер (`shops.whatsapp`), IP и User-Agent в сессиях. Копии — в бэкапах, логах (IP), письмах (почта уходит SMTP-провайдеру), журнале ошибок (T-605).
- **Закон № 94-V** (по вторичным источникам, проверено 2026-11-15; юристом не подтверждено):
  - ст. 12 — персональные данные хранятся в базе на территории РК; с 25.08.2026 — «в базе и (или) цифровом объекте», то есть и файлы, бэкапы, хранилища;
  - ст. 10-1 (с 25.08.2026) — уведомление о начале обработки, сведения вносятся в реестр;
  - ст. 16 — передача за рубеж (иностранный SMTP, облачный журнал ошибок, прокси перед сайтом) не запрещена: в страны, обеспечивающие защиту персональных данных, — свободно, в остальные — с согласия человека или по другим основаниям закона. Локализация (ст. 12) касается того, где хранится база, а не того, какими сервисами мы пользуемся.
- **Зона .kz:** сайт в зоне .kz должен размещаться на сервере в Казахстане (правило регистратора, страница домена .kz на ps.kz). Витрины — `<поддомен>.<сервис>.kz` (ADR 0001).
- Нагрузка: пилот — 1–5 магазинов, до 100 без деградации (NFR-3); профиль — чтение каталога, тяжёлое (фото, импорт) — в процессе `worker` (T-607). Бюджет не главное ограничение (решение основателя).

## Варианты
Зарубежные провайдеры (DigitalOcean, Hetzner и т. п.) отпадают: и закон, и зона .kz требуют сервера в Казахстане. Цены — на 2026-11-15, тенге в месяц.

1. **ps.kz, VPS** (Basic-4: 4 разделяемых vCPU, 8 ГБ, 160 ГБ SSD — 28 750). Казахстанская компания с 2003 года, дата-центры в Алматы и Астане, своё S3 (стандартное — 12,53 за ГБ, архивное — 8,08 за ГБ), домены .kz. Минусы: на 2026-11-15 заказ VPS в Алматы приостановлен (есть ли VPS в Астане — не проверено); DNS-записи только вручную в кабинете, API есть лишь для регистрации доменов; публичной статус-страницы нет.
2. **ps.kz, облачные серверы** (почасово, из ресурсов: 4 vCPU / 8 ГБ / 80 ГБ — около 47 000). Гибче, но дороже; на 2026-11-15 в Алматы и Астане не выдают публичные IP (Floating IP).
3. **Servercore** (облако Selectel для Центральной Азии, казахстанское ТОО): в Алматы облачные серверы на KVM (~35 000), S3 (`kz-1`, 15,60 за ГБ), DNS-хостинг с API, почтовый сервис; заказ открыт. Минусы: модуль Caddy для их DNS, по всей видимости, не подходит (`caddy-dns/selectel` — только API Selectel), так что DNS всё равно отдельно; сеть в Казахстане — партнёрская, 13.05.2026 DDoS на неё дал ~9,5 ч перебоев; бренд связан с российской компанией; независимых отзывов нет.
4. **hoster.kz** (4 vCPU / 8 ГБ / 200 ГБ NVMe — 23 040): дешевле всех, но без S3 — своё хранилище и его бэкапы на нас.
5. **Yandex Cloud, регион kz1**: полное облако, но дата-центр в Караганде с одной зоной и российская компания. **QazCloud**: для крупного бизнеса, цены по запросу.

Рядом с выбором провайдера:
- **Оркестрация:** Kubernetes (у ps.kz — от 26 940 за каркас) и Docker Swarm решают задачу многих серверов; у нас один сервер — Docker Compose (как в ADR 0001).
- **Хранилище файлов:** своё (SeaweedFS на VPS) — бесплатно, но диск сервера, обновления и бэкапы на нас; S3 провайдера — три копии, обслуживать нечего, сервер остаётся почти одноразовым.
- **База:** управляемый PostgreSQL ps.kz (от 11 365) — реплика и бэкапы кнопкой; PostgreSQL в Docker на VPS — дешевле, бэкапы делаем сами (T-604).
- **DNS:** зона у ps.kz — без API, Caddy не выпустит wildcard-сертификат сам (Let's Encrypt проверяет `*.<домен>` только через DNS, сертификат продлевается каждые ~60 дней); зона у провайдера с API.

## Решение
Решение основателя (2026-11-15): **ps.kz**. Если заказ VPS ещё приостановлен — ждём или берём VPS в Астане.

| Что | Как |
|---|---|
| Сервер | VPS Basic-4 (4 vCPU, 8 ГБ, 160 ГБ SSD), Алматы или Астана. 8 ГБ — запас под пики `worker` (сжатие фото, импорт) рядом с PostgreSQL: на 4 ГБ в пик ядро убивает процессы |
| Устройство | Docker Compose на одном сервере, как в ADR 0001; без Kubernetes и Swarm |
| База | PostgreSQL в Docker на VPS; бэкапы — T-604 |
| Файлы | Объектное хранилище ps.kz, стандартный класс: публичный и закрытый бакеты (вместо MinIO из ADR 0001; в разработке по-прежнему SeaweedFS) |
| Бэкапы | Архивный класс S3 ps.kz в другом городе, не там, где сервер (T-604) |
| Домен | .kz у ps.kz (9 590 в год) |
| DNS | Зона в Cloudflare, только DNS (без проксирования — «серое облако»): в записях нет персональных данных. Caddy выпускает wildcard-сертификат через модуль `caddy-dns/cloudflare` |
| Итого | около 30 000 в месяц на пилот (сервер, S3, домен) |

Почему ps.kz, а не Servercore: дешевле, фиксированный месячный тариф, казахстанская компания, сервер и S3 в стране; главное преимущество Servercore — DNS с API — для Caddy, по всей видимости, не работает, а остальное у обоих есть. Переезд между провайдерами при Docker Compose — вечер работы, ошибка выбора стоит недорого.

## Последствия
- **T-602:** заказ VPS (уточнить в поддержке: виртуализация KVM, образ Ubuntu 24.04), бакеты S3, домен, NS-серверы домена → Cloudflare, Caddy с `caddy-dns/cloudflare`, `api` и `web` только во внутренней сети Docker, `TRUST_PROXY=loopback, uniquelocal` ([api.md](../api.md), «Ограничение частоты»).
- **Внешние сервисы за рубежом можно** (решение основателя 2026-11-16). Условие — либо в них не уходят персональные данные, либо передача указана в согласии и политике конфиденциальности (ст. 16). Выбор между своим и облачным сервисом — по удобству и цене, а не по закону:
  - журнал ошибок (T-605) — облачный Sentry без персональных данных (не слать IP, почту, cookie и тела запросов) или свой GlitchTip / Sentry;
  - почта (T-603) — иностранный SMTP-провайдер можно, если указан в политике;
  - прокси Cloudflare перед сайтом на пилоте не включаем — он не нужен; включить — через него идут cookie и почты при входе, значит, сначала строка в политике;
  - CDN для картинок — без условий: в публичном бакете только фото товаров и логотипы, это не персональные данные (scaling.md, SC17).
- **Политика конфиденциальности** должна перечислять внешних обработчиков, которых мы используем (почта, журнал ошибок и др.), — сверить её текст с этим списком перед пилотом.
- **DDoS:** на пилоте — ограничения частоты в коде; сетевую защиту, если понадобится, — услугой ps.kz (казахстанской, закону не мешает).
- **Второй сервер** — по признакам из [scaling.md](../scaling.md) (раздел 6): сначала вынести базу или взять управляемую базу ps.kz с репликой, потом несколько копий API за балансировщиком.
- **Не решено, нужно до пилота** (open-questions): подтверждение вывода по закону юристом; оператор данных (ИП или ТОО), уведомление по ст. 10-1; согласие на обработку персональных данных и политика конфиденциальности при регистрации.
