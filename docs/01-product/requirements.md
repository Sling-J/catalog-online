# Требования к MVP (ТЗ)

Основа: [mvp-scope.md](mvp-scope.md) (решения D…), [user-stories.md](user-stories.md). Технические решения (стек, хранение, API) здесь не фиксируются, они в [02-architecture](../02-architecture/README.md).

Пункты с пометкой **[предложено]** приняты основателем как значения по умолчанию (2026-10-31).

## 1. Предметная модель (понятия)

| Понятие | Что это | Ключевые поля |
|---|---|---|
| Магазин | Клиент сервиса | название, поддомен, WhatsApp, логотип, контакты, адрес, график, ссылки на соцсети, статус (черновик / опубликован / заблокирован), настройки показа остатка |
| Категория | Раздел каталога магазина | название, родитель (до 2 уровней) **[предложено]**, порядок |
| Атрибут | Характеристика варианта: размер, цвет, объём… | название, список значений, порядок значений (S < M < L) |
| Товар | Карточка в каталоге | название, описание, категория, фото, видимость, ключ группы из импорта |
| Вариант | Конкретная позиция товара | артикул (уникален в магазине), штрихкод, значения атрибутов, цена, остаток |

У товара без размеров и цветов ровно один вариант. Цена хранится на варианте (размеры могут стоить по-разному), на витрине у товара показывается «от X ₸», если цены вариантов различаются.

## 2. Витрина (покупатель)

**FR-V1. Открытие каталога.** Магазин доступен по `<поддомен>.<сервис>.kz`. Первый экран: шапка магазина и сетка товаров. Если каталог не опубликован или магазин заблокирован, показывается заглушка.

**FR-V2. Категории.** Список категорий магазина (только с товарами в наличии), переход в категорию показывает её товары и товары подкатегорий.

**FR-V3. Поиск.** По названию товара, без учёта регистра, с частичным совпадением. Работает внутри текущей категории и фильтров.

**FR-V4. Фильтры.**
- По значениям атрибутов, которые встречаются в текущей выборке (например, размеры 98, 104, 110).
- По диапазону цены.
- Товар попадает в выборку, если у него есть хотя бы один вариант в наличии, подходящий под фильтр.
- Товары без остатка по умолчанию скрыты. Настройка магазина «показывать отсутствующие» выводит их в конце с пометкой «нет в наличии» **[предложено]**.
- Фильтры отражаются в URL, ссылкой можно поделиться.

**FR-V5. Сортировка.** Новые (по умолчанию), цена по возрастанию, цена по убыванию.

**FR-V6. Карточка товара.**
- Галерея фото (свайп), название, цена, описание, категория.
- Выбор варианта по атрибутам; недоступные комбинации неактивны.
- Наличие по выбранному варианту согласно настройке магазина (FR-A8).
- Кнопка «В корзину» активна только при выбранном варианте в наличии.

**FR-V7. Корзина.**
- Хранится в браузере покупателя, отдельно для каждого магазина.
- Изменение количества (не больше остатка, если он известен), удаление, итоговая сумма.
- При открытии корзины цены и наличие перепроверяются, изменения показываются покупателю.

**FR-V8. Оформление заказа.**
- Одна кнопка «Заказать через WhatsApp». Покупатель ничего не вводит (D11); опционально поле «Комментарий» **[предложено]**.
- Заказ не сохраняется (D14); остатки не меняются.
- Открывается WhatsApp (ссылка `wa.me/<номер магазина>?text=…`) с текстом:
  ```
  Здравствуйте! Заказ с сайта <Магазин>:
  1. Куртка зимняя (Размер: 110, Цвет: синий) × 1 — 25 000 ₸
  2. Шапка (Размер: 52) × 2 — 7 000 ₸
  Итого: 39 000 ₸
  ```
- После отправки корзина очищается, показывается экран «Заявка ушла в WhatsApp» со ссылкой повторно открыть WhatsApp.
- Защита от спама: ограничение частоты заказов с одного устройства/IP **[предложено]**.

**FR-V9. Информация о магазине.** Контакты, адрес (ссылка на 2ГИС/карты), график работы, ссылки на Instagram и WhatsApp.

## 3. Админка магазина

**FR-A1. Регистрация и вход.**
- Регистрация по email + пароль с подтверждением email **[предложено: email дешевле SMS; вход по телефону можно добавить позже]**.
- Вход, выход, восстановление пароля по email.
- Пока почта не подтверждена, можно всё, кроме публикации витрины (решение основателя 2026-11-02, `04-design/admin.md`, A9).
- Один аккаунт = один магазин (D10).

**FR-A2. Мастер настройки и публикация.**
- Шаги: название → поддомен → номер WhatsApp → логотип (можно пропустить).
- Поддомен: латиница, цифры, дефис, 3–30 символов, уникален, список зарезервированных слов (www, admin, api…).
- Магазин создаётся в статусе «Черновик», витрина недоступна. Кнопка «Опубликовать» и «Снять с публикации».
- Чек-лист готовности на главной админки: настройки заполнены, товары загружены, есть фото.

**FR-A3. Импорт Excel/CSV.**
- Форматы: `.xlsx`, `.csv` (UTF-8 и Windows-1251, разделители `;` и `,`). До 20 000 строк **[предложено]**.
- Скачиваемый шаблон. Одна строка = один вариант.

  | Колонка | Обязательна | Назначение |
  |---|---|---|
  | Артикул | да | Уникальный ключ варианта в магазине, по нему обновляем |
  | Название | да | Название товара |
  | Цена | да | Число, ₸ |
  | Остаток | да | Целое ≥ 0 |
  | Код товара | нет | Объединяет строки в один товар с вариантами; если пусто, группируем по точному совпадению названия |
  | Штрихкод | нет | Для будущих интеграций и поиска |
  | Категория | нет | Путь вида `Девочки / Куртки`; несуществующие создаются |
  | Описание | нет | Текст |
  | Любые другие колонки | нет | Считаются атрибутами: заголовок = имя атрибута, значение ячейки = значение (например, «Размер», «Цвет») |

- Шаг сопоставления колонок: если заголовки файла не совпадают с шаблоном (например, выгрузка из учётной системы), пользователь указывает соответствие; сопоставление запоминается для следующих импортов.
- Предпросмотр: сколько товаров/вариантов будет создано, обновлено; список ошибок по строкам (пустой артикул, цена не число, дубль артикула). Строки с ошибками пропускаются, остальное можно применить.
- Применение: новые артикулы создаются, существующие обновляются (цена, остаток, атрибуты, категория, название). Фото, описание и видимость, отредактированные вручную, импортом не перезаписываются **[предложено]**.
- Артикулы, отсутствующие в файле: опция «обнулить остаток» (по умолчанию включена) или «не трогать» **[предложено]**.
- История импортов: дата, файл, итог, ошибки.

**FR-A4. Фото.**
- До 10 фото на товар, JPEG/PNG/WebP/HEIC, до 15 МБ каждое; загрузка с телефона и компьютера, несколько за раз.
- Порядок перетаскиванием, первое — обложка.
- Автоматическое сжатие и несколько размеров для витрины.
- Фильтр «товары без фото» в списке.

**FR-A5. Товары.**
- Список с поиском, фильтрами (категория, без фото, скрытые, нет в наличии) и сортировкой.
- Редактирование товара: название, описание, категория, видимость, фото; таблица вариантов: атрибуты, цена, остаток, артикул, штрихкод.
- Ручное создание товара и вариантов (на случай мелких правок без импорта).
- Массовые действия: скрыть/показать, сменить категорию.

**FR-A6. Категории и атрибуты.**
- Категории: создать, переименовать, переместить, удалить (товары остаются без категории), порядок.
- Атрибуты: создать, переименовать, порядок значений (для размеров).
- Выбор, какие атрибуты участвуют в фильтрах витрины.

**FR-A7. Заказы.** ~~Исключено из MVP (D14, 2026-10-31).~~ Ниже — описание на будущее.

**FR-A7 (вне MVP). Заказы.**
- Список с фильтром по статусу, новые выделены; счётчик новых в меню.
- Карточка: номер, дата, позиции с текущим остатком по каждой, сумма, комментарий.
- Статусы и переходы:

  ```
  Новый ──подтвердить──▶ Подтверждён ──выдать──▶ Выдан
    │                       │
    └──отменить──▶ Отменён ◀┘
  ```
- Перед подтверждением менеджер может изменить количество или удалить позиции (покупатель договорился в WhatsApp).
- Подтверждение списывает остатки. Если остатка не хватает — предупреждение, подтвердить всё равно можно (остаток не уходит ниже 0) **[предложено]**.
- Отмена подтверждённого заказа возвращает остатки.
- Поле для заметки менеджера (например, телефон покупателя из WhatsApp).
- Новые заказы, не обработанные N дней, автоматически не отменяются (в MVP), только подсвечиваются.

**FR-A8. Показ остатка (D5).**
- Режим: «есть / мало / нет» (по умолчанию) или точное число.
- Порог «мало»: по умолчанию ≤ 2 **[предложено]**.

**FR-A9. Настройки магазина.** Название, логотип, описание, WhatsApp, контакты, адрес, график работы, соцсети, показ отсутствующих товаров, смена пароля.

**FR-A10. Статистика (C).** Просмотры витрины и товаров, количество нажатий «Заказать через WhatsApp» за период (D14).

## 3a. Лендинг сервиса (D13, добавлено 2026-10-31)

**FR-L1.** Главная основного домена: оффер, проблема → решение, «как это работает» в 3 шагах (загрузите Excel → добавьте фото → делитесь ссылкой), демо-каталог, FAQ, контакты.
**FR-L2.** Основной призыв «Создать каталог» ведёт в регистрацию (FR-A1); вторичный — «Посмотреть пример» открывает демо-магазин.
**FR-L3.** Визуально сильный дизайн с «вау»-эффектом; при этом первый экран на мобильном 4G — до 2,5 с (NFR-2), индексируется (NFR-5).

## 4. Суперадминка

**FR-S1.** Список магазинов: название, поддомен, дата регистрации, статус, число товаров, нажатий «Заказать» за 30 дней; поиск.
**FR-S2.** Блокировка/разблокировка магазина (витрина показывает заглушку, ~~вход в админку запрещён~~ владелец входит в админку и видит статус «Заблокирован» — так в экранах A27; решение основателя 2026-11-09, T-403).
**FR-S3.** Вход в админку магазина «от его имени» с записью в журнал действий.

## 5. Уведомления

**FR-N1.** ~~Исключено из MVP (D14).~~ Email магазину о новом заказе **[предложено: бесплатно; позже Telegram-бот или WhatsApp]**. Можно отключить.

## 6. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | Mobile-first: витрина рассчитана на телефон, админка удобна и с телефона, и с компьютера |
| NFR-2 | Скорость: первый экран витрины на мобильном 4G — до 2,5 с; список товаров — бесконечная прокрутка или пагинация |
| NFR-3 | Объём: до 20 000 вариантов и 5 000 фото на магазин; до 100 магазинов на пилоте без деградации |
| NFR-4 | Изоляция: данные магазина видны и меняются только им (и суперадмином) |
| NFR-5 | SEO и шаринг: страницы витрины индексируются, у товаров корректное превью (Open Graph) в WhatsApp/Instagram/Telegram |
| NFR-6 | i18n: все тексты UI через систему переводов, деньги в ₸ с разделителями разрядов, даты по часовому поясу магазина |
| NFR-7 | Безопасность: HTTPS, хранение паролей по стандарту, защита от перебора паролей, ограничение частоты запросов |
| NFR-8 | Надёжность: ежедневные резервные копии данных и фото, восстановление не дольше суток |
| NFR-9 | Персональные данные: покупателей не храним (D11); данные магазинов — по законодательству РК (уточнить требования о локализации данных) |
| NFR-10 | Наблюдаемость: журнал ошибок и базовые метрики, чтобы видеть сбои импорта и заказов |
