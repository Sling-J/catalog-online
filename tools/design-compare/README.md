# design-compare — сверка экрана с макетом

Одна команда открывает артборд холста (`design/canvas/boards`) и экран приложения на той же ширине в установленном Google Chrome (без окна), сопоставляет тексты и печатает расхождения: положение, размер, шрифт, цвет и подложку (кнопка, чип, поле, плашка). Нужен затем, чтобы код повторял макет (решение основателя, T-114) без ручных замеров в браузере.

## Запуск

Дев-сервер должен работать: админка — конфигурация `admin-check` в `.claude/launch.json` (http://localhost:3012, моки там работают), витрина — `web` (http://aigerim-kids.localhost:3000).

```bash
pnpm design:compare --board AdminPhone --list
pnpm design:compare --board AdminPhone --frame "Товары" --url http://localhost:3012/products
pnpm design:compare --board AdminProductsStates --frame 3 --url "http://localhost:3012/products?q=пуховик"
```

| Параметр | Что это |
|---|---|
| `--board` | доска из `design/canvas/boards`, без `.dc.html` |
| `--frame` | номер экрана на доске или часть его заголовка; `--list` покажет все |
| `--url` | экран приложения; размер окна берётся из артборда (390×844, 1440×900) |
| `--init` | JS до загрузки страницы: например, сессия моков в `localStorage` |
| `--before` | JS после загрузки, можно `await`: открыть шторку, выбрать строки |
| `--wait` | пауза после загрузки и после `--before`, мс (800) |
| `--tol` | допуск по положению и размеру, px (1) |
| `--max-shift` | дальше этого одинаковый текст считается другими данными, px (24) |
| `--shots <папка>` | снимки `design.png` и `app.png` — смотреть глазами |
| `--json` | отчёт в JSON |

Код выхода 1, если есть расхождения.

Пример с действием — выбрать три строки таблицы и сверить полосу массовых действий:

```bash
pnpm design:compare --board AdminDesk --frame 1 --url http://localhost:3012/products \
  --before "for (const row of [...document.querySelectorAll('[role=row]')].slice(1, 4)) row.querySelector('[role=checkbox]').click()"
```

## Как читать отчёт

- **Расхождения** — пары с одинаковым текстом, у которых отличаются положение, размер, шрифт, цвет или подложка. Это то, что надо исправить, если причина не в данных.
- **Только в макете / только в приложении** — тексты без пары. Обычно это другие данные: в моках другие товары и числа (37 товаров вместо 214 в макете). Если там подпись интерфейса, а не данные, — элемент пропущен или текст отличается.
- Данные сдвигают и соседей: чип «Все 37» уже, чем «Все 214», поэтому следующие чипы в отчёте левее на несколько пикселей. Такие сдвиги не ошибка вёрстки.
- Доли пикселя от разных метрик шрифта (в макете Geologica из Google Fonts, в приложении — вариативная со своего сервера) отсекает допуск `--tol`.
- Без текста элементы (фото, иконки, переключатели) сверяются только через подложку соседнего текста; их проверяйте по снимкам `--shots`.

## Устройство

- `src/board.ts` — артборд как обычная страница: без рантайма холста, фото `/_blob/<id>` — из `design-assets/storefront` по таблице в `design/canvas/README.md`.
- `src/collect.ts` — замеры внутри страницы (выполняется через `page.evaluate`, поэтому без импортов): тексты, подсказки полей, выбранный вариант `<select>`, ближайшая подложка (не выше 120 px), видимое скругление с учётом обрезки родителем.
- `src/compare.ts` — сопоставление по тексту (ближайший по положению) и отчёт; тесты — `src/__tests__`.
- `src/cli.ts` — запуск Chrome (`playwright-core`, канал `chrome`; браузеры playwright не скачиваются), полоса прокрутки в приложении скрыта, как в макете.
